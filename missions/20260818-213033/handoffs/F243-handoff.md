## Decisions made
- AUTONOMOUS_DECISION (spec's own "Notes for clarification," resolved per the clarification's Round B "simpler option, no new dependency, no second source of truth" rule): recents stored in **localStorage**, not a new Supabase table. Unlike `board_swimlane_prefs` (F226) — a small, intentional, server-read-at-page-load setting — "recently visited items" is a high-frequency, disposable, per-device browsing log with no other reader in the product; adding a table would mean a migration, RLS policy, and network round trip on every navigation purely to remember UI history. Explicitly NOT cross-device, per the spec's own note.
- Storage shape carries **only** `{type, id, visitedAt}` — never a cached name/title/key. This is the actual mechanism behind "must not confirm the item exists": even if an attacker inspected a shared device's localStorage, they'd learn only an opaque id, not what it was. Every render re-resolves via `resolveRecentItems`, which re-checks the caller's CURRENT visibility through the same RLS-scoped session client (`createClient()`, never `createAdminClient()`) `searchPalette` (F242) already uses — a dropped pointer and a never-existed pointer are indistinguishable in the response, matching `lib/views/resolve-view.ts`'s (F229) "dangling reference degrades gracefully" convention this feature's Correctness points explicitly pointed at.
- AUTONOMOUS_DECISION: added `resolveRecentItems` to the existing `lib/actions/palette-search.ts` rather than a new Server Action file. This widens this feature's Files footprint slightly beyond the spec's own approximate list (`components/command/actions.ts`, `command-palette.tsx`, `lib/hooks/use-recent-items.ts`), but is the only way to satisfy this feature's own explicit "must not leak" correctness requirement (a server round trip re-checking live visibility is unavoidable for that guarantee) — and F242's own handoff already flagged this exact file/seam as where F243's recents would need to hook in. No other file outside the spec's list, or outside this one closely-related extension, was touched.
- AUTONOMOUS_DECISION: "Create task" and "Create project" **navigate** to the existing projects list page (where `NewProjectDialog`/`NewTaskDialog` already live) rather than performing the mutation inline in the palette. Task creation requires a `projectId` the palette has no context for on an arbitrary workspace page, and both dialogs are full, permission-checked forms (name/description, or title/priority/assignees) not reasonably reconstructed inline within this feature's scope. This keeps `createProject`/`createTask` (already re-verified server-side via `canWrite` + `requireActiveMembership`) as the ONLY mutation path — no parallel Server Action was added, satisfying this feature's "must reuse existing Server Actions rather than parallel ones" requirement. Enforcement therefore lives exactly where the spec asked ("enforced in the ACTION, not by hiding UI"): the palette's `isVisible` filter is a UX nicety, and the real gate is `createProject`/`createTask`'s own existing server-side re-check, unchanged by this feature.
- "Toggle theme" performs its effect directly (no navigation, no Server Action) via `next-themes`' `setTheme` — the same client-only mechanism `components/theme-toggle.tsx` already uses. There is nothing server-side to mutate for a per-device theme preference.
- Recents tracking is scoped to visits made **through the palette itself** (selecting a search result or a recent item calls `addRecent`) — board/task-detail pages outside this feature's Files list are not instrumented. Documented as Out-of-scope below.
- Reused `PALETTE_RESULT_CAP_PER_GROUP`'s sibling convention for a `RECENT_ITEMS_CAP = 5` (both stored-pointer count and rendered-row count per type) — no assertion mandates an exact number.
- The empty-query state's rendering priority changed from F242's bare "Type to search..." text to Actions (always at least "Toggle theme") + Recent (when present), falling back to the original neutral text only when neither exists (unreachable in practice today, since Toggle theme is always visible, but kept for defensiveness/future-proofing if the action registry is ever emptied for a role). Updated F242's own `test_AS_466_empty_query_shows_neutral_prompt_not_no_results` test to match — AS-466's real guarantee (no "no results" state on an empty query) is unchanged.
