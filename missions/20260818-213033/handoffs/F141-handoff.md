## Decisions made
- Action-to-sentence mapping location (clarified spec's explicit "keep this mapping in one place" requirement): kept entirely inside `lib/queries/audit.ts` as `actionSentence()`, alongside `targetHref()` and `KNOWN_AUDIT_ACTIONS` — the single file the feature spec already named, rather than a new `lib/activity/*` file. `components/audit/audit-table.tsx` imports both functions from there rather than re-implementing any part of the mapping, so there is exactly one place that knows what an `action` string means for display purposes.
- `actionSentence()` builds each sentence from the actor's already-resolved display label plus the entry's own `metadata` jsonb (per F140's own convention: "put any additional structured detail ... in metadata") — no extra DB lookups per row beyond the one batched `resolvePeople` call for actors. Covers exactly the 14 action strings F140 shipped (`KNOWN_AUDIT_ACTIONS`), with a generic (but still sentence-shaped, never a raw key) fallback for any future action not yet in that list.
- `canViewAudit` (lib/auth/permissions.ts) already existed — added by F139 alongside its RLS policy specifically so the DB and app layers can't drift, per that feature's own handoff. Reused verbatim rather than adding a second predicate.
- Pagination/"load more" (definition of done: "bounded window... not an unbounded query"): implemented as a `limit` URL search param that bumps by `DEFAULT_AUDIT_PAGE_SIZE` (100) per click, re-running one bounded `.limit(limit + 1)` query (fetching one extra row to detect `hasMore` without a separate `count` query) rather than true keyset/cursor pagination. Chosen as the simpler option consistent with this codebase's existing URL-round-trip filter convention (`ListFilters`) — no new client-side accumulation state, no second pagination mechanism introduced. `AuditFilters` deletes the `limit` param whenever a filter changes, so a new filter combination always starts from its own fresh first page rather than an unrelated stale window size.
- `components/audit/audit-filters.tsx` was added beyond the feature spec's literal Files list (which named only `audit-table.tsx`), because AS-248 explicitly requires actor/action filtering and this codebase's established convention (`components/task/list-filters.tsx`, F054) is a dedicated small Client Component for exactly this — mixing a "use client" filter bar into the same file as the Server Component `audit-table.tsx` isn't possible (the directive is file-scoped), so a second file within the already-named `components/audit/` directory was the only way to follow the existing pattern. Recorded here per the clarified spec's "stay in scope, report the rest" — this stays inside the feature's own component directory, not a wider expansion.
- Actor filter options are sourced from the workspace's current active members (`getWorkspaceMembers`, pre-existing from F017/F122) rather than a `select distinct actor_id` over `audit_log` — simpler, no second query pattern, and consistent with how `ListFilters`' assignee dropdown already sources its options. Tradeoff: a past actor who has since left the workspace won't appear as a selectable filter option (though their existing entries still render correctly in the table, since actor display data is resolved per-row independent of current membership). Not flagged as a gap because AS-248 only requires "can be filtered by actor," not "every historical actor is selectable."
- Target links (`targetHref`) are best-effort, not always a deep link to the exact row: `workspace_member`/`workspace` targets link to the members/settings pages generally (no per-row deep-link route exists for an individual membership or the workspace itself), `project`/`project_member` link to the project page when a usable id is available (via `target_id` or `metadata.project_id`), and anything else renders a plain em-dash rather than a broken link. This is a UI nicety, not itself asserted by AS-246/AS-248, so the simpler "link where sensible, dash otherwise" approach was taken per the clarified spec.
- `Button`'s `asChild` prop doesn't exist in this codebase's `components/ui/button.tsx` (a thin `@base-ui/react/button` wrapper) — the "Load more" control is a plain `<Link>` styled with the exported `buttonVariants` class-name function instead of the shadcn-style `asChild` composition other codebases use.
