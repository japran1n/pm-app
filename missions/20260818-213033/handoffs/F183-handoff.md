## Decisions made
- **"Save as template" placed in the task detail Sheet's footer, next to "Delete task"** — the spec's Notes said to mirror wherever "Duplicate" (F180) lives, but F180's own handoff explicitly records it shipped as a Server Action only, with NO UI wiring anywhere (flagged as that feature's own out-of-scope work). With no existing "Duplicate" menu location to mirror, and no context-menu convention anywhere on `task-card.tsx` (checked — no `DropdownMenu`/`MoreHorizontal` pattern exists on either the card or the sheet), the simplest option per this feature's own ambiguity-resolution rule was a second footer action next to the sheet's only other terminal action, matching that button's own gated/disabled/tooltip convention exactly (`canWrite`, mirroring `saveTaskAsTemplate`'s own server-side gate). Did NOT add a "Duplicate" UI entry — that's F180's own explicitly out-of-scope work, not part of this feature's Files/assertions.
- **"New from template" implemented as a standalone picker dialog (not a form-prefill inside `NewTaskDialog`)** — chosen because `createTaskFromTemplate` is a complete, already-tested, one-call task-creation path (F182) that needs no client-side form state at all; re-deriving a "load payload into the New Task form's fields" flow would duplicate `createTaskFromTemplate`'s own server-side logic (assignee-membership re-check, checklist copy, status default) on the client for no benefit, and risks the two paths drifting. The picker is placed next to `<NewTaskDialog>` everywhere it already renders (board toolbar, board empty state, list toolbar) — the "board's quick-add menu" the spec refers to, since this codebase's board has no separate per-column quick-add row; the toolbar's `<NewTaskDialog>` trigger already *is* that project's one quick-add entry point (confirmed by reading `board.tsx`/`board-empty-state.tsx`/list `page.tsx` — no other quick-add exists).
- **`templates` fetched server-side per project page (board + list), not via a client-side Server-Action list call** — per the clarified "server-fetched in the page and passed down as typed props; client components never query Supabase directly for initial render" answer. Added `getWorkspaceTaskTemplateOptions` (id/name only) alongside the fuller `getWorkspaceTaskTemplates` (name/creator/date/preview) used by the `/templates` page itself, in the same new `lib/queries/templates.ts` file — one query module backing both consumers rather than two.
- **New `canManageTemplate` predicate added to `lib/auth/permissions.ts`** rather than inlining an ad-hoc `isCreator || isAdminOrOwner` check in the templates list component — per the clarified "controls are hidden or disabled through lib/auth/permissions.ts" answer and this module's own AS-230 single-source-of-truth convention. It mirrors `renameTemplate`/`deleteTemplate`'s exact server-side rule (creator OR workspace admin/owner) using the existing `isResourceOwner` helper already in that file, rather than reimplementing ownership comparison a second time.
- **Payload preview shows the template's saved title + a truncated (140-char) description snippet**, not the full checklist/assignee/tag contents — the spec's Notes left "how much detail" open; took the simpler option (title + description are the two fields a human recognises a template by at a glance) rather than rendering every field, avoiding a second, denser preview-rendering surface for data already fully visible once the template is actually applied.
- **Sidebar "Templates" entry gated non-guest**, exact same convention as "Archive"/"Members" (`isGuest` filter in `navItems`) — the templates page itself independently redirects a guest who navigates there directly (same "redirect away, not just hide UI" convention F142's archive page and F141's audit page both use), matching CLAUDE.md's "follow the established gating convention" instruction in this feature's assignment.
- **Empty state on `/templates` reuses the exact structural pattern** (muted-circle icon, heading, one-line explanation) from `components/board/board-empty-state.tsx`/the archive page's own empty state — inline JSX rather than a new shared component, matching the archive page's own precedent of inlining this pattern per-page rather than always factoring it out (board-empty-state.tsx is the one case that WAS factored out, because it's reused across two render paths on the same page; `/templates` only renders it once).
