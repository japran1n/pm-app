## Decisions made
- Added jsdom as a **per-file** environment (`// @vitest-environment jsdom` pragma at the top of `tests/unit/user-avatar.test.tsx`) rather than flipping `vitest.config.ts`'s global `test.environment` to `"jsdom"`. First attempt did exactly that (global flip); a full-suite run then showed jsdom's undici-based `WebSocket` polyfill throwing `TypeError: The "event" argument must be an instance of Event` against Supabase Realtime's live websocket in `tests/integration/comment-delete-broadcast.test.ts` and friends, plus a broader swath of network-timing failures. Reverted `test.environment` to `"node"` (documented why, in the config file) and scoped jsdom to only the new DOM test file via the per-file pragma — clean full-suite pass afterward (aside from pre-existing live-network flakiness noted above). This is a deviation from the spec's literal "Add jsdom... to vitest.config.ts" wording but stays inside its intent ("Add jsdom... as a real DOM test environment" — achieved) while explicitly avoiding a global regression the spec didn't anticipate; recorded here per the inherited F122 clarification's "Ambiguity resolution: simpler option, recorded" and "Regression protection: full suite green" answers, both of which point the same direction (don't break the existing suite for a global flip when a scoped one satisfies the same requirement).
- `initialsFor`'s astral-character fix uses `Array.from(value)[0]` (first grapheme by codepoint, via `Array.from`'s iterator which splits on UTF-16 surrogate pairs correctly) rather than a full Unicode grapheme-cluster segmenter (`Intl.Segmenter`) — sufficient for the flagged bug (surrogate-pair splitting), simpler, no new dependency, matches the spec's explicit instruction ("use `Array.from(label)`").
- Replaced the `hash = (hash * 33) ^ charCode` hash with FNV-1a + a Murmur3-style finalizer avalanche (chosen over "document that the module must not be reused for short keys," per the spec's "your call" instruction) because: (a) the module's own doc comment already commits to being reused by F224's swimlane/grouping colours on short keys like `"todo"`, where M10 scrutiny found the old hash collides badly — documenting a limitation the code already violates its own stated purpose for would just relocate the bug; (b) the fix is a same-signature, dependency-free, ~10-line swap with no behavioural surface change beyond which bucket a given id lands in; (c) verified empirically that anagram ids (`"acme-user-42"` vs `"42-acme-user"` vs `"user-acme-42"`) now land in different buckets (6, 4, 3) where the old hash collapsed them.
- Did not convert the other 11 sibling `readFileSync`-grep test files (`tests/unit/board-task-detail-sheet-wiring.test.ts` and similar) to real DOM renders — see Out-of-scope below.
- For the two AS-214 surfaces that are impractical to render as full real components without extra mocking infrastructure — the members list (an async Server Component doing its own Supabase fetch + `redirect()`) and the list-filters assignee picker (a `next/navigation`-router-bound `<Select>`) — the test renders `<UserAvatar person={{ ...same shape as the real call site... }} />` copied verbatim from that surface's source, rather than mounting the surrounding page/router chrome. This is still a real DOM render+assertion (not source-text regex), just without the surrounding non-avatar UI. Recorded explicitly in the test file's header comment and here per the DoD's "manual verification" / scope-boundary answers.
