# F015 — Proposal card + diff rendering

## Files
- `components/ai/proposal-card.tsx` (new)
- `components/ai/diff-view.tsx` (new)

## Rules
- Three visual states, and they must be unmistakable at a glance:
  - **pending** — attention-toned card, diff visible, Accept + Reject
  - **accepted** — collapses to a single success-toned row, diff hidden
  - **rejected** — collapses to a single neutral row, diff hidden
- Tokens only. See F009's constraint on the sand/green semantics.
- Diff: added lines marked with a leading `+` **and** a background tint — colour alone
  must not be the only signal (AS-069, and it is the right thing regardless).
- Long diffs scroll inside their own `overflow-y` container; the sidebar itself never
  scrolls sideways.
- Show a compact count ("4 lines added, 1 removed") so a collapsed card still says
  what happened.
- If the diff library from tech-decisions is not needed, do not add it. A line-level
  LCS over `split("\n")` is ~40 lines and avoids a dependency. Decide, and record why.

## Assertions
AS-064, AS-066, AS-069, AS-070

## Out of scope
Actually applying the edit — that is F016. This component only reports the user's choice.

## Tokens — see the RESOLVED section in F009.md
`--status-waiting` / `--status-waiting-bg` for pending, `--status-done` / `--status-done-bg`
for accepted, `--muted` / `--muted-foreground` for rejected. No new tokens, no hex literals.

For the diff itself, added lines use `--status-done-bg` as the tint and removed lines
`--status-blocked-bg` (`#b8332a` at 16%) — both already exist. The `+` / `-` markers carry
the meaning independently of colour.
