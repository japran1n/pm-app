# F005 — Tool: list_doc_templates

## Goal
Expose the team's document templates so the model drafts to a house structure
instead of inventing one.

## Files
- `lib/ai/tools/list-doc-templates.ts` (new)
- `lib/ai/tools/__tests__/list-doc-templates.test.ts` (new)
- possibly `supabase/migrations/<ts>_task_templates_doc_kind.sql` (new, only if needed)

## Investigate first
`task_templates` currently carries `kind='task'`. Determine whether a CHECK constraint,
an enum, or RLS forbids `kind='doc'`. Read the F181 migration and any later ones.
- If `'doc'` is already permitted: no migration, say so in the handoff.
- If it is blocked: add a migration that widens the constraint. Do NOT drop and recreate
  the table. Follow the header-comment convention used by existing migrations —
  they explain *why*, at length. Match that.

## Output data
`{ templates: Array<{ id, name, sections: string[], rules: string[], tone: string | null, folderHint: string | null }> }`

Templates are stored as a JSON payload on the existing template row; define the shape
in `lib/validation/` alongside the existing template schemas and parse defensively —
a malformed payload must yield `ToolEmpty`, not a crash.

## Assertions
AS-024, AS-002, AS-028

## Out of scope
A UI for creating templates. Reading only. Template authoring is a later feature.
