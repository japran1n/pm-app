## RESOLVED BY ORCHESTRATOR (2026-09-09) — do not re-investigate
`supabase/migrations/20260822180000_task_templates.sql:46` defines:
```sql
kind text not null default 'task' check (kind in ('task', 'project'))
```
So `'doc'` **is** blocked. A migration IS required. Widen the CHECK to
`('task', 'project', 'doc')` — do not drop the constraint, and do not recreate the table.

That migration's header comment explains the single-table-with-discriminator design at
length and explicitly anticipates new kinds. Read it before writing yours, extend its
reasoning rather than restating it, and note that `payload` is deliberately opaque jsonb
validated at the Server Action layer by Zod — NOT by a DB CHECK. Follow that same split:
your doc-template payload schema belongs in `lib/validation/`, not in SQL.

Also update the table/column `comment on` text to mention `kind='doc'`, as the existing
migration does for its two kinds. The comments in this codebase are treated as documentation.
