# F016 — Apply accepted edit

## Goal
The single, narrow, auditable write path.

## Files
- `lib/actions/ai-proposals.ts` (new server action)
- wiring in `components/ai/proposal-card.tsx`

## Rules
- This is an ordinary server action with `"use server"`, called from a click handler.
  It is NOT reachable from a tool, and the AI layer must not import it (AS-003 stays true).
- Signature: `applyDocEditProposal({ docId, expectedCurrentMarkdown, proposedMarkdown })`.
- **Stale check**: re-read the doc; if its markdown no longer equals
  `expectedCurrentMarkdown`, return an error telling the user the document changed and
  the proposal must be regenerated. Do not silently overwrite someone else's edit.
- Write through the existing docs update path in `lib/actions/docs.ts` so RLS,
  `revalidatePath` and any audit behaviour all apply identically to a human edit.
- Reject performs **zero** calls. Not a no-op write, not a status update — nothing
  touches the database (AS-010).
- On success the open editor view updates without a full page reload.

## Assertions
AS-009, AS-010, AS-065, AS-002

## Out of scope
Undo. Worth having, but it is a separate feature and the diff card plus normal doc
history already covers the common case.
