# F028 — Conversation history in the route (M1e; unblocks AS-047 and AS-061)

## The gap
`app/api/ai/docs/route.ts:176-178` passes `messages: [{ role: "user", content: body.message }]`.
`threadId` is parsed at line 44 and **dropped**. There is no conversation history at all.

Every HTTP request is turn 1. Ask "summarise the roadmap", then "make it shorter", and the model
receives only "make it shorter" with no referent. The assistant is functionally amnesiac.

Consequences beyond the obvious:
- **AS-047** is about "the second turn of a conversation" reporting `usage.cached > 0`. With no
  history, a second turn cannot exist, so the assertion is unverifiable rather than merely unmet.
- **AS-061** ("navigating to another doc without losing the thread") is at risk before M2 starts.
- The cacheable prefix is currently ~1.5 KB of system prompt, plausibly **below the model's
  minimum cacheable prefix** — in which case `cache_read_input_tokens` stays 0 forever while
  every test passes. Conversation history is what pushes the prefix over that threshold.

Retrofitting this after the sidebar is built is materially more expensive, which is why it comes
before M2 rather than with F019.

## Scope
Accept a client-supplied `messages` array (prior turns) on the request, validated with Zod:
- cap the number of turns and total characters — an unbounded client-supplied history is both a
  cost and a prompt-injection surface
- roles restricted to `user` / `assistant`
- reject anything else with a clear `error` event

Do **not** build the `ai_threads` table here — that is F018, and server-side persistence replaces
this client-supplied path later. This feature exists so the route is *shaped* for history now, so
F008/F019 do not require a route rewrite.

## Verify the cache actually works
Emit `usage.cached` (F007 already does). Then run a real two-turn exchange **if
`ANTHROPIC_API_KEY` is available**, and record the observed `cache_read_input_tokens` in the
handoff. If the key is absent, say so plainly — AS-047 then remains BLOCKED, not PASS. Do not
assert caching works from placement alone; the M1 review specifically flagged that the existing
AS-047 tests check `cache_control` placement and never touch `usage`.
