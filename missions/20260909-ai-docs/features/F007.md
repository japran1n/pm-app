# F007 — Route handler with streaming + tool loop

## Goal
The one HTTP entry point. Auth, stream, tool loop, caps, clean errors.

## Files
- `app/api/ai/docs/route.ts` (new)

## Shape
- `export const runtime = "nodejs"` — NOT edge. Supabase server client and the SDK
  both need Node APIs.
- `POST` only. Body: `{ threadId?: string; message: string; currentDocId?: string }`.
- **Auth first, before any model call** — `auth.getUser()`; 401 and return immediately
  if absent. A billed call for an unauthenticated request is a defect (AS-007).
- Returns a `ReadableStream` of newline-delimited JSON, exactly the envelope in
  `tech-decisions.md`. One JSON object per line, `\n`-terminated.

## Must handle
| Case | Behaviour |
|---|---|
| No `ANTHROPIC_API_KEY` | Open the stream, emit one `error` with code `no_api_key`, then `done`. HTTP 200. Never a 500 (AS-045) |
| Anthropic 429 | `error` code `rate_limited` (AS-046) |
| Anthropic 4xx/5xx | `error` code `upstream`, message safe for display |
| Client aborts | Propagate `AbortSignal` to the SDK call so the upstream stream is torn down (AS-044) |
| >8 tool calls in one turn | Stop, emit `error` code `tool_limit`, then `done` (AS-048) |

## Tool loop rules
- Every `tool_start` gets exactly one `tool_end` with the same id — including when the
  tool throws. A tool that throws emits `tool_end` with an error summary (AS-042).
- A write tool returning a proposal emits `proposal` and the turn ENDS. Do not let the
  model continue as though the edit were applied (AS-043).
- Emit a final `usage` event with input/output/cached token counts before `done`.

## Assertions
AS-007, AS-040, AS-041, AS-042, AS-043, AS-044, AS-045, AS-046, AS-048, AS-105

## Out of scope
Persistence (F018/F019) and rate limiting (F020). Accept a `threadId` and ignore it
for now; do not invent a schema here.

## Done when
A contract test can POST with a stubbed model and assert the exact event sequence.
