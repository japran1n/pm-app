# F034 — Per-turn ownership in the streaming hook (fixes M-majors 1/2/3, B2)

Four defects in `lib/ai/use-doc-assistant.ts`, all one family: nothing is scoped to the turn that
produced it.

1. **`stop()` and `reset()` don't stop event application.** The read loop (`:275-300`) never checks
   `controller.signal.aborted`, and `applyEvent` (`:124`) isn't scoped to its controller. Probed: a
   message grew *after* `stop()`; a `reset()` conversation repopulated itself. In M3 this lets a
   stale stream resurrect a settled proposal.
2. **No unmount cleanup — the hook has no `useEffect` at all.** After unmount the IIFE keeps
   reading and calling `setMessages`, the reader is never cancelled, and the model keeps generating
   and billing.
3. **F028's conversation history is dead on arrival.** The route accepts `messages` (`route.ts:86`,
   read at `:203`) but the hook sends only `{workspaceId, message, currentDocId}` (`:248-254`).
   The assistant is amnesiac; F028 is entirely unwired and nothing detected it.
4. **Non-2xx discards the real server message** (`:258-265`) — 401, 400 and 403 all collapse into
   one opaque string, so session expiry is indistinguishable from a bug. That path also never
   cancels `response.body`.

Also: `tool_start` after `tool_end` regresses a finished call to a permanent spinner (`:151`).

## Fix
Pass the controller into the event loop; bail on `controller.signal.aborted` before every
`applyEvent` and each read. Add a `useEffect` cleanup that aborts and `reader.cancel()`s on
unmount. Replace the `err.name === "AbortError"` check at `:302` with `controller.signal.aborted`
— undici rejects as `TypeError: fetch failed` with the abort in `.cause`, and jsdom's
`DOMException` is not `instanceof Error`. Send accumulated history mapped to `historyTurnSchema`,
trimmed to the route's `MAX_HISTORY_TURNS`. Surface the server's message on non-2xx and cancel the
body. Guard the tool-status transition so `running` cannot overwrite a finished call.
