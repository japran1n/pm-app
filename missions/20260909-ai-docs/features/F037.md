# F037 — Assistant markdown theming and IME safety

## M4 — assistant text may render near-black on the dark panel
`assistant-thread.tsx:55` applies `prose prose-sm`. `app/globals.css:4` loads
`@tailwindcss/typography`, but there is **no `prose-invert` and no `--tw-prose-*` override
anywhere** in `app/` or `components/`. `.prose` sets `color: var(--tw-prose-body)` = `#374151`,
with headings/bold/code at `#111827`, overriding the wrapper's `text-foreground`.

On the dark `--background` panel that is near-black on near-black.

**This was inferred from CSS, not confirmed in a browser** — and `components/docs/markdown-editor.tsx:252`
has the same bare `prose`, so either this is a pre-existing app-wide defect or something
compensates that static reading missed. **Confirm in a browser first.** If the docs editor is fine
today, find out why before changing anything, and say what you found.

**Fix (once confirmed):** add `prose-invert`, or map `--tw-prose-*` onto the design tokens. Do not
introduce colour literals.

**Consider instead:** replace the read-only TipTap instance with a lightweight markdown renderer
for assistant turns. The M2 review measured the current approach round-tripping ~3.2 MB of markdown
for a 4 KB answer across 400 deltas, because `assistant-thread.tsx:67-71` calls `getMarkdown()`
(a full serialise) then `setContent` (a full re-parse) per token. **That guard is near-dead code
regardless** — markdown serialisation is not identity-preserving (`*em*` → `_em_`), so
`current !== text` is almost always true, and the effect only fires when `text` changed anyway.
**Delete the guard now** whichever path you choose.

Also pin the XSS behaviour with a test: `<script>` and `onerror` must never survive rendering. That
guarantee currently exists only as a transitive TipTap StarterKit default, with nothing asserting it.

## M5 — no IME composition guard
`assistant-composer.tsx:92-100` checks only `e.key === "Enter" && !e.shiftKey`. No `isComposing`,
no `keyCode === 229`. A CJK user pressing Enter to commit a candidate submits raw partial text and
the textarea clears.

`components/chat/message-composer.tsx` has the same gap, so this is inherited, not new — but the
composer's header comment cites that file at length without noting it.

**Fix both**, so the app has one correct Enter convention rather than two wrong ones. Touching the
existing chat composer is deliberate and in scope here.

## Minors to fold in

  `scrollHeight - clientHeight`). Browsers clamp so it is harmless, but `f010:156` asserts
  `scrollTop === scrollHeight`, which is only true because the test's stub setter stores unclamped
  — a mirror-of-implementation test. Fix both.
- `decoder.decode(value, {stream:true})` never gets a final flush call, so a multibyte character
  split across the last chunk is lost.
