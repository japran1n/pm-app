# F014 — Tool: propose_doc_edit

## Goal
The first tool the model can aim at an existing document — and the one that must
never write. This feature is where the mission's central safety rule becomes code.

## Files
- `lib/ai/tools/propose-doc-edit.ts` (new)
- `lib/ai/tools/__tests__/propose-doc-edit.test.ts` (new)
- `lib/ai/tools/__tests__/no-writes.test.ts` (new) — see below

## Input
`{ docId: string; instruction: string }`

## Behaviour
1. Read the doc (reuse F003's reader — do not duplicate the query).
2. Ask the model — a **separate, non-streaming** call — to return the full revised
   markdown. Reuse `getAnthropicClient()`; effort `"high"`; this is a quality-sensitive
   generation, unlike the chat turn that triggered it.
3. Compute a line diff between current and proposed.
4. Return a `DocEditProposal`. **Return. Do not write.**

## The no-writes test (this is the point of the feature)
`no-writes.test.ts` greps every file under `lib/ai/tools/` for `.insert(`, `.update(`,
`.delete(`, `.upsert(` and `rpc(` and fails the suite if any appears. It must be a real
test in the normal `npm test` run, not a script someone has to remember to run.
This encodes AS-003 so a future worker cannot quietly regress it.

## Rules
- `currentMarkdown` in the envelope is the exact text the diff was computed against.
  F016 compares it before applying and refuses if the doc has since changed.
- If the model returns markdown identical to the current text, return `ToolEmpty` with
  `no_results` and a message saying no change was needed. Do not emit an empty diff card.
- Never propose an edit to a doc the caller cannot see — `get_current_doc` semantics apply.

## Assertions
AS-003, AS-025, AS-043, AS-028
