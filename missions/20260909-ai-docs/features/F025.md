# F025 — Fix the abort path (fixes B3)

## Why
`app/api/ai/docs/route.ts:338-340` — `cancel()` calls `abortControllerCancelNoop()`, a
module-scope zero-argument function (line 352) that cannot reach the per-request
`abortController` closure inside `start()`, and never sets `closed`.

Scenario: user clicks stop. `fetch` aborts → body cancelled → controller closes → `finish()`
(line 214) runs with `closed` still `false` → `controller.close()` on an already-closed
controller → `TypeError`, thrown past the `finally` at 334. **An unhandled rejection on every
aborted request** — the exact path AS-044 exists to cover. The upstream Anthropic stream is
also never torn down, so billing continues for a response nobody reads.

## Fix
- `cancel()` must be a closure with access to the request's `abortController`: set `closed = true`
  **and** call `abortController.abort()`.
- Guard `send()` on `closed` / `signal.aborted` so nothing enqueues after close.
- Make `finish()` idempotent.

## Test — must actually abort
The current test (`f007-docs-agent-route.test.ts:265-281`) asserts
`options?.signal instanceof AbortSignal`, which a fresh never-aborted signal passes identically.
That is not a test of aborting.

Write one that starts the stream, reads a chunk, **cancels the reader mid-stream**, and asserts:
1. no unhandled rejection,
2. the signal passed to the SDK is actually aborted,
3. nothing is enqueued after cancellation.
