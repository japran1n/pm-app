# F002 — Tool result envelope + shared schemas

## Goal
One shared vocabulary every tool returns, so the route handler and the UI never
special-case a tool. Pure types + tiny helpers. No I/O, no network, no DB.

## Files
- `lib/ai/tools/types.ts` (new)

## Contract
```ts
export type ToolOk<T>    = { status: "ok";    data: T };
export type ToolEmpty    = { status: "empty"; reason: "not_found" | "not_visible" | "no_results"; message: string };
export type ToolError    = { status: "error"; code: string; message: string };
export type ToolResult<T> = ToolOk<T> | ToolEmpty | ToolError;
```
Plus the proposal envelopes the write tools return (they never mutate):
```ts
export type DocEditProposal = {
  kind: "doc_edit";
  proposalId: string;      // crypto.randomUUID()
  docId: string;
  docTitle: string;
  currentMarkdown: string; // what the proposal was computed against
  proposedMarkdown: string;
  summary: string;         // one line, human-facing
};
export type DocCreateProposal = {
  kind: "doc_create";
  proposalId: string;
  title: string;
  markdown: string;
  folderId: string | null;
  templateName: string | null;
};
```

## Rules
- `ToolEmpty` is a normal outcome, never an exception. A tool that cannot see a row
  returns `empty`, not `error`. This is what makes RLS isolation invisible to the model.
- `ToolError.message` must be safe to show a user and must never contain a key,
  a token, a connection string or a raw Postgres error (AS-105).
- `currentMarkdown` exists so F016 can detect that the doc changed under the proposal
  and refuse to apply a stale edit.

## Assertions
AS-021 (shape), AS-027 (shape), AS-105

## Out of scope
Any actual tool. Any Zod schema for tool *inputs* — those live with each tool.

## Done when
`npx tsc --noEmit` passes and the file exports exactly the types above.
