# F024 — Replace tautological isolation tests with real-DB ones (fixes B2)

## Why
All 18 tool tests pass in 398 ms because none touches a database. The isolation tests assert
against their own mocks — `get-current-doc.test.ts:74` (AS-008) is byte-identical to the
not-found test at line 63. **None would fail if RLS were dropped or a service-role client used.**

This repo already rejects this approach in writing:
`tests/integration/palette-search-private-project-leak.test.ts:1-19` — *"This mission has had
repeated real privilege-escalation bugs in exactly this shape… this test proves that end-to-end,
not by code review alone."*

## Fix
Follow that file's pattern exactly. Read it first; it is the reference implementation.

Create real-database isolation tests for all three tools:
- two users, two workspaces, both genuinely existing in the DB
- a doc and a doc-template that really exist in workspace B
- the caller authenticated in workspace A gets **nothing** — not a filtered mock, an actual RLS denial

The live remote Supabase is reachable from this environment (F005 applied a migration through
`db:apply` successfully), so these can genuinely run.

Place them in `tests/integration/` — this is the legitimate case for that directory, and say so
in the handoff.

## Verify the tests can fail
Before finishing, temporarily point one tool at a service-role client and confirm the new test
**fails**. Then revert. Record that you did this. A test that cannot fail is worse than no test,
because it produces confidence instead of coverage.

## Keep the fast mocked tests
Do not delete the existing unit tests — they usefully cover shape, truncation and empty paths.
Just stop them claiming to prove isolation: rename those specific cases and strip the isolation
language from their comments so no future reader is misled.
