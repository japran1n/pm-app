# F020 — Guards: rate limit, cost ceiling, error states

## Files
- `lib/ai/guards.ts` (new), plus wiring in the route handler and the sidebar

## Rules
- Per-user throttle on `/api/ai/docs`. In-memory is acceptable for a single-instance
  deployment **only if** the handoff says so explicitly and names what would break on
  multi-instance. Prefer a DB-backed counter if one already exists in the codebase.
- Per-thread token ceiling; when exceeded, `error` code `thread_limit` with a message
  suggesting a new chat.
- Every `error` code from tech-decisions renders as a human sentence in the sidebar.
  `no_api_key` is a configuration state, not a failure — no red styling for it.
- Audit pass for AS-105: confirm no key, token, or raw Postgres error can reach a log,
  an NDJSON event, or a persisted `ai_messages` row. Grep for `console.log` under
  `lib/ai/` and `app/api/ai/` and remove or route through the existing logger.
