## Decisions made
- **B5 fix — moved `ToolCallList`/error into `AssistantThread`'s own scroll region** rather than just slapping `overflow-y-auto` on the outer wrapper alone. `AssistantThread` added an optional `trailing` prop rendered inside its existing `role="log" aria-live="polite" overflow-y-auto` div, so tool cards and the turn error scroll with the thread as one region instead of being unshrinkable siblings of a non-scrolling parent — and get announced by the same `aria-live` region (the separate aria-live minor from the spec). The outer wrapper (`assistant-sidebar.tsx`'s thread-region `<div>`) additionally kept `overflow-y-auto` itself as a second line of defence, since it's also what renders when `messages.length === 0` (the empty-state branch never mounts `AssistantThread` at all).
- **B6 fix — `window.innerWidth` + `resize` listener instead of `window.matchMedia`.** Grepped the whole test suite; no `matchMedia` polyfill exists anywhere (jsdom in this repo's config has no implementation — confirmed by a throwaway test asserting `typeof window.matchMedia === "function"`, which failed). `window.innerWidth` IS real in jsdom and defaults to 1024 (below the 1180px breakpoint), which conveniently means jsdom's default state already exercises the overlay path — the tests set it explicitly either way via `Object.defineProperty` + a dispatched `resize` event.
- **B6 fix — Escape via the shared escape-layer stack** (`lib/hooks/use-shortcut.ts`'s `useEscapeLayer`), the same primitive `components/task/image-lightbox.tsx` uses, rather than a second document keydown listener. Cooperates with `ShortcutProvider`'s single global handler instead of risking double-handling.
- **B6 fix — no reusable focus-trap utility existed in the codebase** (grepped `trapFocus`/`focus-trap`/`useFocusTrap`; only `image-lightbox.tsx` has Escape+backdrop+restore-focus, no Tab-wrapping trap). Wrote a small local `useEffect` in `AssistantSidebar` scoped to `isOverlay`: on entry, saves `document.activeElement`, moves focus to the panel's first focusable element (or the panel itself), and installs a `keydown` Tab handler that wraps focus at the panel's first/last focusable elements; on exit, restores focus to whatever was focused before the overlay opened. Not extracted to a shared hook since this is the only place in the codebase that currently needs conditional (viewport-gated) focus trapping — flagged under Out-of-scope for extraction if a second consumer appears.
- **B3 fix — omitted the chips rather than disabling them** when `hasApiKey` is false (spec offered either). Disabling would still put a dead, focusable-but-inert control in the DOM for no benefit; omitting means there's nothing to accidentally trigger `send` from, and nothing a screen reader announces as interactive-but-broken.
- **B3 fix — exposed `reset` as a "New conversation" button** in the context bar, visible whenever `messages.length > 0`, rather than only surfacing it in the no-key dead-end. This covers B3's literal "no way back" concern generically (any dead-end thread, not only the no-key one), and is a strict improvement with no new failure mode — clicking it just clears local hook state (already covered by `useDocAssistant`'s existing `reset` behaviour, F008).
- **Persistence key scoping — parsed the workspace slug straight off `usePathname()`** inside `assistant-sidebar.tsx` itself (a new `useWorkspaceSlugFromPath` hook, same shape as the existing `useCurrentDocIdFromPath`) rather than threading `workspaceId` through `AssistantSidebarProvider` in `app/(workspace)/w/[workspaceSlug]/layout.tsx`. Editing `layout.tsx` is outside this feature's Touches (not listed in the spec, and it's the orchestrator-owned mount point per F009's own header comment); the slug-from-URL approach fixes the actual bug (state leaking between workspaces) with zero changes outside `components/ai/`.
- **Composer focus-loss minor — `readOnly` instead of `disabled`** while streaming, per the spec's own suggestion. `canSubmit` already guards against submitting while streaming, so Enter-to-submit stays a no-op; only the value-change path needed the guard, which `readOnly` provides without making the element unfocusable.
- **`--line-row` misuse fix — both flagged instances (`assistant-sidebar.tsx:242` chip border, `tool-call-card.tsx:148` list border) changed to `border-border`.** `divide-line-row` in `tool-call-card.tsx` was correctly left alone (it's a genuine row separator, not a panel/control border) — matches the spec's own note that only the `border` utility was wrong there.

## Autonomous decisions
AUTONOMOUS_DECISION: Used `window.innerWidth` + a `resize` listener instead of `window.matchMedia` for the "is this currently the narrow overlay" check, because this codebase's jsdom test setup has no `matchMedia` implementation and no existing polyfill for it anywhere in the suite (verified with a throwaway test). `innerWidth` is real in jsdom, keeps the implementation testable without adding a new polyfill file, and is checked against the same `1180px` breakpoint the existing Tailwind `max-[1180px]:` classes already use, so the JS-side state and the CSS-side layout switch can't drift apart.
AUTONOMOUS_DECISION: Scoped the persistence key by workspace SLUG (parsed from the URL inside `assistant-sidebar.tsx`) rather than by `workspaceId` threaded through the provider from `layout.tsx`, since `layout.tsx` is outside this feature's Touches and the slug is already available via the exact same `usePathname()` parsing pattern the file uses elsewhere (`useCurrentDocIdFromPath`).
AUTONOMOUS_DECISION: For B3, chose to OMIT the chips (not disable them) when `hasApiKey` is false — the spec explicitly offered either option ("disable or omit").
AUTONOMOUS_DECISION: Exposed `reset` as a generic "New conversation" affordance (shown whenever `messages.length > 0`) rather than only in a no-key-specific dead-end branch, since the spec's own B3 writeup frames "no way back" as a general problem ("a dead-end thread"), not one scoped only to the no-key case.
