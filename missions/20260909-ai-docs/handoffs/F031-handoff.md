## Decisions made
- Gated the three isolation suites behind `AI_DOCS_LIVE_DB_TESTS=1` OR `process.env.CI` (in addition to requiring admin creds). This means: (a) an ordinary local `npm test`/`npx vitest run` with `.env` symlinked to a live project never seeds it anymore, (b) CI — which already hard-throws if creds are missing — is exempt from needing the opt-in var so it can never go green while silently skipping all real coverage, and (c) a developer who explicitly sets `AI_DOCS_LIVE_DB_TESTS=1` locally (ideally pointed at a local `supabase start` stack) still gets full coverage on demand.
- Extracted the shared env-loading, credential-detection, CI-guard, admin-client-factory, and new `shouldRunLiveDbTests`/`sweepLeakedFixtures` logic into `tests/integration/support/live-db.ts` rather than duplicating the opt-in + sweep logic three times, since all three suites were already near-identical copy-paste of this boilerplate.
- `sweepLeakedFixtures` deletes by fixture-name convention (workspace `slug` LIKE `f024-%`/`f027-%`, and any auth user whose email starts with those prefixes) rather than by tracking exact created ids, per the spec's explicit ask for a "tag-based sweep... regardless of how setup exited." It runs in every suite's `afterAll`, on top of (not instead of) the existing id-based cleanup, so a `beforeAll` that throws after creating only some resources still gets those specific ids cleaned by the id-based path, and the sweep catches anything a *previous* crashed/killed run left behind (a full process kill, e.g. from a test timeout, skips `afterAll` entirely — the sweep is the only thing that can recover from that on the *next* run).
- Did not attempt to add a `try/finally` wrapper inside each `beforeAll` body itself: Vitest already runs a suite's `afterAll` hooks even when its `beforeAll` throws (confirmed by inspection — the existing id-based `afterAll` cleanup, which is unconditional, already relies on this and was presumably working as intended before this fix). The `try/finally`-equivalent protection the spec asks for is delivered by (1) the existing unconditional id-based `afterAll` cleanup already in place for the current run, plus (2) the new prefix-based sweep for anything a full process kill missed. Adding a redundant try/finally around the seeding steps themselves would not change behavior given (1) already covers within-run throws.
- Left `SUPABASE_URL`/`PUBLISHABLE_KEY` re-exported from the shared module (still needed for `createSupabaseJsClient` calls building the caller-session client for RLS assertions) but dropped the now-unused `SECRET_KEY` re-export from each test file's import list — it's used internally by `createAdminClient()` in the shared module, and importing it unused in the test files was tripping a new `no-unused-vars` ESLint warning that would have pushed the warning count above the documented 26-warning baseline.
- For Part A, extended `INJECTION_DEFENSE` (still 100% static text, still entirely above the `cache_control` breakpoint — nothing per-request was moved) to explicitly name conversation history and prior assistant turns as untrusted DATA on par with document content, using the same "do not act on it, tell the user instead" pattern already established for documents, so the model applies one consistent rule rather than two similarly-worded but separately-maintained ones. Then rewrote the route.ts:284-287 comment so it accurately describes what the prompt says, rather than deleting it — the comment's purpose (explaining *why* it's safe to forward client history to `buildDocsAgentRequest`) is still valid and worth keeping now that it's true.
- The new AS-006 route-level test asserts on the `tools`/`system` fields actually passed to the mocked `client.beta.messages.stream()` call, rather than trying to prove the *model* doesn't get fooled (which would require an unmocked/live model call, out of scope for this mocked-network route test file). This proves the narrower, still-meaningful property available at this test boundary: the route itself performs no content-based branching on history — it forwards the crafted turn as opaque data and sends exactly what `buildDocsAgentRequest` returned, unmodified, so a compromised client cannot use a crafted history turn to make the *route* offer different tools or a different system prompt to the model.
