## Decisions made
- `propose_doc_edit`'s `run` reuses `get_current_doc`'s exported `run` function directly (not a re-query of `docs`) — this is both the spec's explicit instruction and what makes the not-found/not-visible collapse (AS-021) and F027's workspace scoping apply here for free, with no second query to drift out of sync.
- Extended the envelope with a `diff` field via `DocEditProposalWithDiff = DocEditProposal & { diff: DocEditDiffLine[] }` defined locally in `propose-doc-edit.ts`, rather than editing `lib/ai/tools/types.ts` (F002, out of this feature's declared "Files" scope). AS-025 requires the envelope to contain "a computed diff"; extending additively (intersection type) satisfies that without touching the shared F002 contract that F017's future `create_doc` also depends on.
- Used `diffLines` from the already-installed `diff@8.0.4` package (present in `node_modules`, listed in tech-decisions.md as "only if a hand-rolled diff proves insufficient" — a hand-rolled line differ would just reimplement `diffLines` worse, so used the library directly).
- The model-generation call in `propose-doc-edit.ts` is `client.beta.messages.create(...)` (non-streaming, awaited), per this feature's spec's explicit instruction ("a separate, non-streaming call"). This is a narrower, feature-specific override of tech-decisions.md's general "Streaming: always" row, which is written in the context of user-facing chat turns (the product requirement it cites is about long user-visible outputs); this internal proposal-generation call has no user-facing token stream to write to, so non-streaming does not violate the spirit of that row. Recorded here rather than silently deviating.
- Used AST-based call-expression matching (`ts.isCallExpression` + `ts.isPropertyAccessExpression` name check) instead of a source-text regex for the no-writes guard, after discovering a flat/whole-file regex over `.insert(`/`.update(`/etc. false-positived on `lib/supabase/server.ts`'s own doc comments (which describe, in prose, the exact calls its preview-write Proxy guard blocks) and its `builderProp === "insert"` string literal comparison. This is a strictly more precise version of the same guard-rail property the spec asked for (grep-for-write-calls), not a weaker one — it can never miss a real call expression, and eliminates false positives from comments/strings that a real grep-based checker would otherwise force every future doc comment near `lib/supabase/server.ts`'s import chain to dance around.

## Out-of-scope work needed

F015's spec should account for splitting `value` on `\n` for line-by-line rendering if a strict one-row-per-line UI is wanted.
