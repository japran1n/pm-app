## Decisions made
- Category is a free-text required Input, matching F049's `createQuestionSchema` (`category` is `min(1)`, not an enum) — no category picker/allowlist exists elsewhere in the codebase to reuse.
- Answer type uses the existing `<Select>` primitive (components/ui/select.tsx), following components/member-role-select.tsx's controlled-Select pattern, with a fixed 4-value enum sourced from `BriefQuestionAnswerType` (lib/queries/brief.ts) rather than re-declaring the list.
- `QuestionForm` is a single component for both create and edit (an optional `question` prop switches mode), calling `createBriefQuestion` or `updateBriefQuestion` respectively and validating client-side first with `createQuestionSchema` / `updateQuestionSchema` — mirrors components/edit-project-dialog.tsx's controlled-form + useTransition + toast pattern.
- `QuestionList` is a Client Component (not a Server Component) because inline edit requires local open/closed state per row; it receives `questions: BriefQuestion[]` as a plain prop from a Server Component caller (matching components/portal/team-answers-view.tsx's data-down pattern) and calls `router.refresh()` after a successful save rather than managing question state itself, since the parent page already re-fetches via `getBrief`.
- Did not wire `QuestionList`/`QuestionForm` into the existing brief page (app/.../brief/page.tsx) or add an "Add question" entry point — out of scope per the feature spec's file list (question-form.tsx, question-list.tsx only). Left for the feature that builds the full questionnaire-builder screen.
- No MCP usage: this is a pure UI feature touching no live external service state (per worker-mcp-usage skill's decision tree — "Pure UI feature → No MCP").
