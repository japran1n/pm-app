- F078 required no schema change and no new table: the brief approval request is already a plain `approval_requests` row (`subject_type: 'doc'`) per F074's design, so it already appears in every existing generic approvals surface (the workspace queue). - F079 required no code change to enforce the assertion — `docs_select_client`'s existing RLS (from F022/F072's era) already conjoins `client_visible` with all three portal conjuncts. Confirmed the portal brief page has no doc link to begin with, so there was no UI leak to close. Tests pin down both the RLS policy shape (source-inspection of the migration SQL) and the absence of a doc link on the portal page, so either regressing would fail loudly.
