## Decisions made
- Precomputed the `hasRevisions` flag per answer server-side in `brief/page.tsx` via `getBriefWithRevisions(brief.id, question.id)`, run in parallel via `Promise.all` across questions — keeps `TeamAnswersView` a pure presentational component (no queries inside it), matching the split `lib/queries/brief.ts`'s own comments describe between reader and presentation.
- "Edited" indicator only shows for answers that are actually answered (text present / at least one option selected) even if `hasRevisions` were somehow true for an empty answer — avoids a confusing badge on a "Not answered yet" placeholder.
- Used the existing `Badge` component with `variant="warning"` for the "Edited" indicator (visually distinct from the `variant="secondary"` answer-type badge and the `variant="outline"` choice chips), consistent with the Supabase design system's badge rules (pill, uppercase, single `text-*`-driven colour, no colour dot).
- Read `components/project-tabs.tsx` before editing: F005's Architecture tab had already landed (concurrent work), so I merged the new Brief tab in alongside it rather than overwriting — added `"brief"` to the `ProjectTab` union, a `pathname?.startsWith(`${basePath}/brief`)` check (placed after the `/architecture` check, before `/hours`, since none of these path prefixes overlap), and a `<TabsTrigger value="brief">Brief</TabsTrigger>` next to the Architecture trigger.
- Did not touch `lib/actions/brief.ts` or `lib/validation/brief.ts` (F049's files), per the task instructions — this feature is read-only against the team side.
