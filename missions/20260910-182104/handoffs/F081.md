## Decisions made
- No code change to `components/architecture/board.tsx` was needed: it already implements F033's hover highlighting with a `useEffect` + vanilla `addEventListener("mouseover"/"mouseleave")` writing `data-hover-component` / `data-component-active` attributes, never `useState`/`useReducer` for hover. Verified by reading the file and by the render-count assertion in the new test (mouseover events fire but the counter never increments).
- No virtualization was added. At 480 plain DOM cards, render time is well under the 2000ms budget (measured ~tens of ms in this test environment) and the board has no scroll-position/windowing requirements that would justify the added complexity of a virtual list. This is documented as a decision, not deferred — a dedicated "does the board render all cards" test asserts exactly `480` card nodes are present in the DOM (no windowing).
- Render time budget test uses `performance.now()` around `render()` from `@testing-library/react`, matching the pattern of other perf-flavored tests in this repo (timing-based, not benchmark.js).
- Mocked `next/navigation` and `@/lib/actions/architecture` the same way `f033-hover-highlighting.test.tsx` does, since `ArchitectureBoard` and its children (`PageColumn`, `SectionCard`) call `useRouter`/`useParams` and the architecture server actions.
