## Decisions made
- Lifted the DndContext from SortableSectionList (per-column, F020) up to ArchitectureBoard (components/architecture/board.tsx), mirroring components/board/board.tsx's own "one DndContext for the whole board" convention — dnd-kit requires a single shared DndContext for a drag to cross between two different SortableContexts (two different pages' section lists).
- board.tsx now owns the optimistic section-order state for every page (`orderByPage`, keyed by page id) and a board-wide `sectionsById` map built from every page's sections — the map is needed because a section optimistically dropped into a DIFFERENT page's column isn't present in that page's own `page.sections` prop until the next server refetch; without the map the destination column would render nothing for it until reload.
- SortableSectionList and PageColumn are now pure renderers: they take `orderedSectionIds`/`sectionsById` from the board and register their own `useDroppable`/`SortableContext`, but hold no drag state and call no Server Actions themselves — board.tsx's single `handleDragEnd` decides same-column (reorderSections, F020's existing action) vs cross-column (new moveSectionToPage) and persists accordingly, with rollback-on-failure via toast, same convention F020 established.
- `moveSectionToPage` re-validates BOTH the section's and the destination page's workspace server-side (independently looked up, never trusting a page id supplied by the client) before writing `parent_task_id`/`position` — same defense-in-depth convention `reorderSections` already uses. `component_id` is never referenced anywhere in the function, so AS-045 falls out structurally rather than needing an explicit "preserve" step.
- Updated tests/unit/f020-reorder-sections.test.tsx to match SortableSectionList's new (post-lift) props (`orderedSectionIds`/`sectionsById` instead of `sections`), wrapped in a `DndContext` since `useDroppable`/`SortableContext` now require a context ancestor that the component itself no longer provides. The "renders nothing when empty" assertion was adjusted to "renders no section cards when empty" since the column's droppable container div is now always present (needed as an empty-column drop target for AS-043), even with zero sections — this is the same F009 "AS-027 board scrolls" invariant, not a behavioral regression for AS-041/AS-042 which this file still fully covers.
