## Decisions made
- lib/validation/architecture.ts's createPageSchema already satisfied AS-018 (min(1) on slug, trimmed) and the nested-slug pattern from F011 already forbids leading/trailing/double slashes, so no change was needed there — only added tests to lock the behaviour in under this feature's assertion IDs.
- Uniqueness check queries `tasks` scoped to `project_id` + `page_slug`, excluding `deleted_at is not null` rows, so a slug freed up by deleting a page can be reused immediately — consistent with every other query in this codebase filtering `deleted_at is null` (lib/queries/architecture.ts convention).
- Uniqueness check runs after permission checks but before the `ensure_task_type` RPC and position count, so a duplicate-slug submission never touches the task-type lookup or does a wasted insert.
- Return shape is the existing discriminated union (`{ ok: false, error }`), not the `{ success, error }` shape sketched in the feature spec, because createPage already returns `{ ok, data } | { ok: false, error }` (F010) — matching the existing action's actual contract instead of the spec's illustrative snippet.
- In create-page-dialog.tsx, added a lightweight heuristic (`error` text contains "slug" or "path") to decide whether the server error renders next to the slug field (with `aria-invalid`/`aria-describedby` wired to a `page-slug-error` paragraph) instead of the generic name-adjacent error paragraph. Both the duplicate-slug message and the regex-validation message from the schema mention "slug"/"path", so both route to the slug-adjacent error correctly.
- Updated tests/unit/f010-create-page-action.test.ts's `tasks` table mock's non-count `select()` branch (previously an unused stub) to return a chainable `{eq, is, maybeSingle}` builder backed by a new `existingSlugRow` shared variable, since createPage now issues that exact query before the insert; this was required for F010's existing tests to keep passing, not a scope change to F010's behaviour.
