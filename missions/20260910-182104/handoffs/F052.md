## Decisions made
- Added `reorderBriefQuestions` to the existing `lib/actions/brief.ts` rather than a new file, per the spec's explicit instruction and to keep all brief-question write actions co-located (matches the file's own existing convention).
- Reorder action does per-row `Promise.all` updates (id -> position) rather than a single bulk upsert, since Supabase's JS client has no simple "update N rows with different values each" primitive; RLS's `brief_questions_update_team` policy is the real permission boundary, matching every other write in this file.
- `QuestionListSortable` mirrors `components/nav/project-nav-list.tsx`'s dnd-kit sensor pairing (PointerSensor + KeyboardSensor + `sortableKeyboardCoordinates`) and its optimistic-update-then-rollback-on-failure pattern, for consistency with the only other drag-and-drop list already in the codebase.
- Component takes `questions: BriefQuestion[]` as a prop (from `lib/queries/brief.ts`), consistent with the spec's stated data source; no membership/write-permission gating added inside this component since the spec didn't ask for it and RLS already gates the actual write — a non-writer's drag would optimistically reorder locally then roll back on the action's error, same UX as `ProjectNavList`'s existing `canReorder` gate would produce if omitted (I did not add a `canWrite` gate here since it wasn't called out in the clarified spec's "Touches" and doing so would mean guessing at how this component receives membership context, which the spec didn't specify).
