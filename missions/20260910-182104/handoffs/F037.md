## Decisions made
- No MCP usage: this is a pure read-only UI feature layered on an
  already-shipped, already-verified query (`getArchitectureBoardForClient`,
  F004). Nothing here touches live Supabase schema/policy state.
- Built dedicated `ClientArchitectureBoard` / `ClientPageColumn` components
  instead of adding a `readOnly` prop to the existing `ArchitectureBoard`/
  `PageColumn` (which are wired to `DndContext`, Server Actions, and
  inline-rename state) — cleanly separates the portal's read-only surface
  from the team board's editing logic without threading conditional
  branches through drag-and-drop code, matching this mission's own
  "Pages" portal view precedent (a dedicated `PagesTable`, not a
  read-only mode bolted onto the team board table).
- `PageKindBadge` is reused as-is (already presentation-only, no editing
  affordance) rather than duplicated.
- Nav: added "Architecture" as an always-shown item in
  `buildPortalNavItems` (same convention as the existing "Pages" item,
  which is also always shown and lets its own empty state carry the "no
  content yet" case) rather than conditionally hiding it — simpler, no
  extra query in the layout, and consistent with how "Pages" already
  behaves for a project with zero shared pages.
- Empty state: "No pages yet" / "Once the team shares a page from this
  project, it will show up here." — no create CTA, per spec (clients
  never create pages/sections).
