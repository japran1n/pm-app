## Decisions made
- Verified live schema via the F045 migration file (`supabase/migrations/20261122020000_f045_brief_answer_revisions.sql`), which already documents (from a live Management API query) that `brief_answer_revisions` has `changed_by`/`changed_at` columns and `changed_by` is an `auth.users` FK with no declared FK to `profiles` — so PostgREST cannot auto-embed a `profiles` join on that column. Implemented the name lookup as a second `profiles` query (`select id, display_name where id in (...)`) over the distinct `changed_by` ids in the answer's revision history, joined in memory, rather than a PostgREST embed.
- Client contacts are identified via the same `profiles` table team members use (F120's `on_auth_user_created` trigger gives every `auth.users` row, including client contacts, a `profiles` row) — there is no separate "client contact" identity shape, so AS-155 needed no new column, just exposing the same `changedByName` field the UI can render for any actor.
- Added `changedByName: string | null` to the existing `BriefAnswerRevision` type (F048) rather than introducing a parallel type, since F048's `getBriefWithRevisions` is the only consumer and the spec explicitly asks to extend that same type.
- Updated `tests/unit/f048-brief-query.test.ts`'s existing `BriefAnswerRevision` literals to include the new required `changedByName` field so the file still type-checks — a mechanical follow-through of the type change, not a behavior change to F048.
