- Did not modify lib/actions/brief.ts: read it and confirmed `deleteBriefQuestion` (added in F049) already does exactly what the spec asks — a plain delete from brief_questions, relying on the DB's `on delete set null` FK and the pre-existing `question_prompt_snapshot` column for AS-110/AS-111. No app-side snapshot logic needed.
- Followed the DeleteWorkspaceDialog / ArchiveProjectDialog confirmation pattern (Dialog + destructive confirm button) rather than `window.confirm`, per the existing codebase convention for consequential deletes, and per the feature spec's explicit dialog copy: "Delete this question? Existing answers will be preserved."

AS-110/AS-111 are verified at the type level by constructing a `BriefAnswer` value with `questionId: null` and a populated `questionPromptSnapshot`, proving the type contract that backs the DB guarantee.
