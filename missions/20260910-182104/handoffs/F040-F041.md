## Decisions made
- Investigated `lib/actions/architecture.ts` first (per the spec's explicit pointer) and found every create/rename/delete/reorder Server Action already re-checks `canWrite({ role: membership.role })` (from `lib/auth/permissions.ts`) after `requireActiveMembership` resolves the caller's real workspace role — this was implemented by earlier F0xx workers (F010 createPage, F013 createSection, F014 renamePage, F017 deleteSection, F018 deletePage, F025 createComponentFromSection, and others) as part of their own feature work, following the exact "defense in depth" convention documented at the top of the file. No source changes were required for F040/F041; this pattern already satisfies AS-089/AS-090/AS-094/AS-097.
- Wrote AS-089/AS-097 tests against the *real* `canWrite` predicate (not a stub that always returns `true`, as most existing architecture tests use for unrelated reasons) so this suite actually proves the writer-vs-viewer decision is enforced, not merely assumed. Mocked only `requireActiveMembership`'s returned role and the DB layer.
- For AS-090 and AS-094, used a source-scan test (reading `lib/actions/architecture.ts` and locating each named function's body) rather than full behavioural stubs, since `createComponent`/`createComponentFromSection`/`reorderSections`/`reorderPages` have heavier DB-shape dependencies already covered by their own features' test files (f025, f028-f030, f031); duplicating that DB mocking here would test the same code path twice without adding assertion coverage. The source-scan confirms `canWrite(` appears in every listed function body, which is the concrete, falsifiable claim AS-090/AS-094 make (a function that silently dropped the check would fail this test).
- AUTONOMOUS_DECISION: Treated `client` role rejection for AS-094 as already covered by the existing generic `canWrite` gate (`canWrite` returns `false` for `isClient(ctx)`), since `reorderSections`/`reorderPages` call the exact same `canWrite` predicate as every writer-gated action — no client-specific branch needed elsewhere. This matches `lib/auth/permissions.ts`'s own documented convention that `canWrite` is "the single generic write gate" all mutating actions share.
