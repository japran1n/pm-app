## Decisions made
- Added `renamePage(taskId, name)` to lib/actions/architecture.ts mirroring the exact membership/permission-check and "confirm it's actually a page" shape `changePageKind` (F016) already established in the same file, rather than inventing a new pattern.
- Validated the name inline with a small ad-hoc Zod string schema (trim, min 1, max 200) matching `createPageSchema`'s `name` field, instead of reusing `updatePageSchema.partial()` (which would require validating an object with only one key touched) -- simpler and just as strict for AS-039.
- `PageColumnHeader` is a small, standalone client component (not baked into `PageColumn` itself) matching the "smallest possible client boundary" convention already used by `PageKindSelector`/`CreatePageDialog`.
- Click and double-click both start editing (spec says "click (or double-click)"); Enter saves, Escape cancels, blur also saves (treated as an implicit Enter, common inline-rename UX, not explicitly required by the spec but does not conflict with it).
- No MCP usage: this is a pure UI/server-action feature already covered by the existing `tasks` table (no schema change), consistent with the mcp-registry decision tree for "pure UI feature" / "no new schema."
