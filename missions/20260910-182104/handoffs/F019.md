## Decisions made
- Chose the "note in the Architecture board page header" approach over adding a per-section-card "Open task" link, per the spec's "pick the simpler approach" guidance. Reasoning: threading `workspaceSlug`/task-detail-link plumbing down through `board.tsx` → `page-column.tsx` → `section-card.tsx` (none of which currently receive `workspaceSlug` or a task-detail URL builder) would touch three additional files outside this feature's stated scope (verifying identity + adding a signal), for a UI affordance that isn't required by AS-004/AS-005's text (both assertions are about a page/section *appearing* in the other view, not about navigating there). A one-line explanatory note directly on the Architecture route achieves the same "this isn't a bug" signal with a single, isolated file change.
- Did not modify `components/architecture/section-card.tsx`, `board.tsx`, `page-column.tsz`, or `lib/actions/architecture.ts` — cross-view identity already exists at the data layer (F010/F013), so no query or action changes were needed; this feature is purely the UI signal plus verification tests.
