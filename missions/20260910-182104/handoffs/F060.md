## Decisions made
- Added an exported `isAnswered(question, draft)` helper in portal-questionnaire.tsx (not a separate module) since the spec's "answers Map or array" signature maps naturally onto the component's existing `draft` state shape (`{ text, options }`), which is what both autosave and the Next-button check already read from.
- Enforcement point is the Next button's onClick handler (`handleNext`): checks `question.required && !isAnswered(...)` and only then sets a `validationError` flag instead of advancing `currentIndex`. Optional/unanswered questions pass straight through.
- `validationError` resets to `false` whenever the question changes (via the existing render-time draft-reset branch) or whenever the user edits the current answer, so the error clears as soon as they act on it rather than following them to the next question or lingering after a fix.
- Required indicator already existed from F055 (`data-testid="questionnaire-required-badge"` Badge showing "Required") — verified present, did not duplicate.
- Single_choice "answered" = exactly 1 selected option (matches F059's radio-group semantics of at most one selection); multi_choice = at least 1.
