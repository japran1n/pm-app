## Decisions made
- The actual portal route tree is `app/(portal)/portal/[workspaceSlug]/p/[projectId]/...` (not the `app/(portal)/p/[projectId]/` path named in the spec's file list) — the spec's literal path doesn't exist in this codebase; every existing sibling portal view (`scope/page.tsx`, `your-list/page.tsx`, etc.) lives under the `portal/[workspaceSlug]/p/[projectId]/` prefix, so I placed `brief/page.tsx` there to match the real, established route tree rather than inventing a second, disconnected portal route group. This is a routing detail, not a deviation from the feature's intent (client-facing brief route under the existing portal shell).
- Access guard: did not add a page-level guard. The parent `[projectId]/layout.tsx` already re-resolves the project via `getPortalProjects` (RLS + `portal_enabled` + client-membership filtered) and calls `notFound()` for anything that doesn't resolve, exactly the pattern every other sibling view under this layout relies on (see `scope/page.tsx`'s own comment) rather than duplicating the check.
- Empty state: used the shared `<EmptyState>` component (icon + title + description + `testId`) already used by `scope/page.tsx` for its own error state, for both the "no brief" and "query failed" cases, per the spec's stub language ("No questionnaire available").
- Answer input: rendered a plain `<Textarea>` stub pre-filled from `initialAnswers` (matched by `questionId`), read-only-in-spirit but left editable and completely unwired — no submit handler, no action call — per the spec's explicit instruction that F059 owns the real per-`answerType` widgets and persistence.
- Test tooling: `@testing-library/user-event` isn't installed in this repo; used `fireEvent.click` (the pattern already used by `tests/unit/add-to-view-menu-membership.test.tsx`) instead. Also had to explicitly import `@testing-library/jest-dom/vitest` and call `cleanup()` in an `afterEach` — this repo's vitest config doesn't enable jest-style globals/auto-cleanup, matching the documented convention in `tests/unit/user-avatar.test.tsx`.
