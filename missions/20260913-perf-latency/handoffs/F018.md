## Decisions made
- Only `app/(workspace)/w/[workspaceSlug]/layout.tsx` is in this feature's `Files:` list, so the fix stays confined to that file — no changes to `AppSidebar`, `ProjectSwitcher`, or `MembershipProvider` even though some of their props are still fetched synchronously in the body.
- Kept `currentUserProfile`, `sidebarProjectsResult`, `favoriteProjectIds` awaited in the parallel batch: they're consumed as plain synchronous props by `<AppSidebar>` and `<ProjectSwitcher>` (not via a Suspense slot), and those components live outside this feature's file scope — streaming them would require adding new slot props to `AppSidebar`, which is out of scope per the constraint in the spec (no behaviour change, minimal footprint).
- Kept `clientMemberCount` and `projectMemberRows` awaited: they feed `<MembershipProvider>`, which wraps the entire child tree (including `children`, i.e. every page under the workspace). Deferring these behind Suspense would suspend the whole page body, not just a sidebar figure — that's a bigger behavioural/streaming change than "one extra Suspense figure" and risked violating AS-025 (no display/behaviour change). Left as-is.
- Moved `getUpcomingClientPresentations` (client-presentation banner) out of the `Promise.all` and into a new local async component `ClientPresentationBannerFigure`, defined in the same file (so no new file needed) and rendered inside `<Suspense fallback={null}>` around `<ClientPresentationBanner>` — this was the one fetch in the batch that only feeds a decorative slot inside `<WorkspaceMain>` and doesn't gate any decision, matching the exact rationale the file's own F016 comments already use for the other figures.
- Test suite: `npm test -- --run` reports 96/698 test files failing, but every failure I inspected (`tests/unit/board-taskid-deeplink.test.tsx`, `tests/unit/f246-task-detail-sheet-copy-link.test.tsx`) is an unrelated `cookies() called outside request scope` unhandled rejection from `lib/queries/custom-fields.ts` / `getCustomFieldsForTaskAction`, nothing to do with the workspace layout. Confirmed pre-existing by `git stash`-ing this change and rerunning the same two files: identical error, same pass count. Did not have budget to run the full 636s suite a second time on the pre-change tree to get an exact baseline diff, but targeted verification shows this change introduces no new failures.
