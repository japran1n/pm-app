## Decisions made
- Added a `visibleProjects` lookup (`select("id") from projects where workspace_id = ... and deleted_at is null`) inside `getWorkspaceListTasks` itself, mirroring the exact pattern `getWorkspaceStatusOptions` (F009, `lib/queries/calendar.ts`) already uses to resolve a workspace's visible project ids before narrowing a downstream query with `.in("project_id", ...)`. Kept it inline rather than accepting `projectIds` as a new parameter, since the function's public signature (`workspaceId`, `filters`, `timezone`) is used by `components/dashboard/dashboard-task-table.tsx` and changing it would be an unnecessary, unrequested signature change — the spec only asks to add the `.in()` predicate.
- Kept the existing `.eq("projects.workspace_id", workspaceId)` and `.is("projects.deleted_at", null)` embedded-table filters in place rather than removing them once the project id list is known — this is strictly additive (narrows before the join runs) and preserves the exact same result set/order per AS-011, avoiding any risk of silently changing behaviour if the two lookups ever raced or the id resolution had an edge case.
- If a workspace has zero visible projects, short-circuit and return `[]` before building the `tasks` query — matches the function's existing "resolves to no matching ids → empty result" precedent used elsewhere in the same function (`assigneeTaskIds`/`blockedIds`).
