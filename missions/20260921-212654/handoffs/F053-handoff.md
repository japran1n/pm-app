## Decisions made
- Modeled the unit-test rewrite on the exact pattern `tests/unit/f009-legacy-portal-route-redirects.test.ts` already established for an equivalent legacy-redirect situation: `vi.mock("next/navigation", () => ({ permanentRedirect: vi.fn((url) => { throw new Error(`NEXT_REDIRECT:${url}`) }) }))`, then `await expect(PageDefault({ params, searchParams })).rejects.toThrow(...)`. This is non-vacuous (removing the `permanentRedirect(...)` call, or changing the URL it's called with, or making the page return normally, all fail the test) and matches an already-reviewed convention in the same repo rather than inventing a new one.
- Modeled the new e2e spec on `tests/e2e/board-reorder.spec.ts`'s real-magic-link auth technique (documented at length in that file) rather than any lighter-weight approach, since it's the established, already-vetted pattern for a real authenticated Playwright test in this repo and the DoD explicitly asked for a test that exercises a real browser navigation, not a mocked one.
- Deleted `notification-bell.tsx` / `notification-bell-figure.tsx` / `NotificationBellSkeleton` only after confirming (via `grep` for the literal import paths, not just the substring "notification-bell" which also matches the still-live `notification-bell-panel.test.tsx` filename and various `notifications-realtime-figure.tsx` header comments) that zero production files import any of the three. F014's own header comment ("leave the figure component file unless unused → delete import only") had left the dead files in place; this feature's own definition of done explicitly calls for deleting them now.
