## Decisions made
- **Kept `buildPortalNavItems` byte-for-byte in its return shape (still exactly 8 items, `toEqual`-tested).** AS-001's own assertion text names exactly eight views; growing that array to include Files/Requests would make AS-001 false on its own text. Added a *separate* `buildPortalSecondaryNavItems(basePath)` instead, rendered in its own section below the eight, so the two contracts (which routes AS-001 promises vs. which routes are merely reachable) stay independently true.
- **Decoupled the topbar's title resolution from the sidebar's nav-item list entirely**, rather than teaching `buildPortalNavItems` about files/requests/task-detail (which would break AS-001's 8-item contract) or teaching the topbar to look at two lists (which is the exact "second list to remember" the spec says to avoid). `resolvePortalStaticTitle` owns its own `STATIC_ROUTE_TITLES` map plus a humanized fallback for anything neither list has heard of — verified by grep that this map is the *only* place file/requests/task-detail titles are named now (`grep -rn "Files\"\|Requests\"" components/portal/portal-topbar.tsx` finds exactly the two entries added).
- **Task-detail title uses a Context ("leaf announces itself upward"), not a static map entry**, because a task's title is data, not a route name, and `PortalTopbar` (part of the shared shell layout) has no `taskId` to fetch with — Next.js layouts only receive route params up to their own segment, and `p/[projectId]/layout.tsx` is one level above `t/[taskId]`. This mirrors a real, provable precedent already in the codebase: `components/nav/breadcrumb-context.tsx` (`useSetBreadcrumb`) solves the identical shape one level up in the app, and `components/project/project-breadcrumb.tsx` + its call site at `app/(workspace)/w/[workspaceSlug]/projects/[projectId]/layout.tsx:110` is a Server Component layout rendering a Client Component leaf that announces data upward into a context a higher ancestor reads — exactly what `PortalTitleProvider` + `PortalTaskTitleAnnouncer` + `PortalTopbar` do here. Also copied that hook's own bugfix (depend on the stable `setTitle` function, not the whole context value object) preemptively rather than reproducing the loop `tests/unit/breadcrumb-context-no-loop.test.tsx` documents.
- **Static fallback for `/t/<taskId>` before the announcer mounts is the literal string "Task"**, not a humanized guess (`humanizeSegment("t")` would give "T"). This only matters for a paint before hydration/effects run (SSR-only, or a slow client) — real title arrives immediately once `PortalTaskTitleAnnouncer` mounts. Verified this actually happens via a real jsdom mount+effect run in `tests/unit/portal-title-context.test.tsx`, not just asserted in a comment.
- **Checked the topbar's "breadcrumb eyebrow" (the small caps line above the title) for the same class of failure, per this feature's own scope item 3, and found none to fix**: it renders `{projectName}` unconditionally — never derived from the nav list, never route-dependent — so it was never at risk of the "Overview" bug. Documented this finding directly in `portal-topbar.tsx`'s own header comment (not just here) so a future reader doesn't re-investigate the same question. This is a negative finding, not a change — no code in that line moved.
- **Removed the `badges` prop from `PortalTopbar`.** It existed solely to build the nav-item list `buildPortalNavItems(basePath, badges)` fed into the old title lookup; nothing else in the component ever used it. Dropping it (rather than keeping an unused, lint-suppressed parameter) is a real cleanup, not scope creep — it was dead the moment the title stopped being looked up in that list. `PortalSidebar` still receives and uses `badges` for its own two badge counts (AS-002/AS-003), untouched.
- **Two new icons (`Paperclip` for Files, `Inbox` for Requests)**, chosen to be visually distinct from the eight primary icons already in use (`FileText` for Pages, in particular) rather than reused, since a client scanning the sidebar should be able to tell the two Files/Pages rows apart at a glance.
