## Decisions made
- Rows rendered via the shared `<Table>`/`<TableRow>` primitive (settings/members, audit log, time report) already carry `hover:bg-muted/50` from the primitive itself (`components/ui/table.tsx`) — no per-page change needed there for rule 3; only non-Table row/list markup (chat nav list, chat search results, docs folder rows, trash list, approvals queue `<table>` rows, client-request cards) needed the hex-hover-to-muted swap or an added hover class.
- No literal `hover:bg-[#ffffff0d]` hex hovers were found under docs/chat/time/calendar/settings/audit/trash/templates/approvals/client-requests — the earlier phases (F028-F035) appear to have already swept the primitives these surfaces build on. This batch focused on the remaining plain `hover:bg-accent`/`hover:bg-accent/50` literals and on adding `font-mono` to data.
- Card-shaped list items (archived project cards, task templates) got `hover-lift` per the shadow/elevation rule instead of a `hover:bg-muted/50`, since they are cards, not table/list rows — matches the three-rules text ("Cards → `hover-lift`; rows → `hover:bg-muted/50`").
- `components/task/task-type-time-card.tsx` and `components/task/time-tracking.tsx` are technically reachable via `find components -iname "*time*"`, but only the former (a small, purely time-value summary card) was in-scope for "ALL time values → font-mono" per F038; `time-tracking.tsx` is the task-detail time-tracking widget, a project/task-detail surface not named in F036-F042's file list — left untouched, flagged below as out-of-scope.
- Settings → status templates' color picker uses a fixed named-color select (`components/workspace/status-template-manager.tsx`), not a raw hex/code text field, so there is no "color value/code" text to make mono — the clarified spec item ("status template color values/codes → font-mono") does not apply to the current implementation; noted as a non-finding rather than skipped work.
