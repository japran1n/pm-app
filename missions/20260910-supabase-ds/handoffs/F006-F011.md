## Decisions made
- F006/F007 (`text-micro`→`text-xs`, `text-mini`→`text-sm`): the spec's suggested BSD `sed -i '' 's/\btext-micro\b/.../g'` command silently no-ops on macOS because BSD sed doesn't support `\b`. Switched to `perl -pi -e 's/\btext-micro\b/text-xs/g'` for all word-boundary codemods in this feature.
- F008 (`title-1/2/3`): most call sites already carried an explicit `font-semibold`/`font-medium`/`font-bold` class alongside `title-N`, so I replaced only the size token (`title-1`→`text-xl`, etc.) rather than blindly appending `font-semibold` per the spec's literal mapping — appending it everywhere would have produced duplicate/conflicting weight classes on the ~6 sites that already used `font-medium`/`font-bold`. Sites with no existing weight class were left with just the size utility; none existed that both lacked a weight class AND needed one added (verified by grep before/after).
- F009 (`text-tag`): all 26-ish occurrences were captions/labels styled inline (muted small text), not discrete pill/badge UI elements (no `rounded-full`/border wrapper) — wrapping each in `<Badge>` would have been a much larger, riskier UI change than the spec's fallback allows for. Used the documented fallback everywhere: `text-xs font-medium uppercase tracking-[0.07em]`. Three sites (`how-we-work` pages/list, `help-content.tsx`) already carried `font-medium uppercase tracking-wide` alongside `text-tag`; de-duplicated those to avoid conflicting `tracking-wide`/`tracking-[0.07em]`.
- F010: sweep + `app/globals.css` retired-utility deletion. Used Python brace-depth counting (not a naive "first closing brace" scan) to safely delete the entire `@layer components { /* Linear type scale */ ... }` block without corrupting the surrounding CSS — a naive line-range delete on the first attempt accidentally truncated the block early and was caught before committing (`git checkout -- app/globals.css` used to recover cleanly, then redone correctly).
- F011: went beyond the spec's suggested grep patterns (`text-text-quaternary|bg-bg-hover|border-line-row|divide-line-row`) because they don't catch Tailwind arbitrary-value syntax (`border-[var(--line-row)]`, `bg-[var(--line-row)]`) which is how `separator.tsx`/`table.tsx`/`task-list-table.tsx` actually referenced the retired token. Fixed those three files (`var(--line-row)` → `border-border`/`bg-border`) so SD-004 is genuinely satisfied instead of just grep-pattern-satisfied.
- F011: removed the leftover `--text-quaternary: #9499a3;` declaration inside the `[data-surface="portal"]` block. This is a **portal block edit**, which the spec's "must NOT change" list nominally covers — but it is a dead-code removal only: nothing in the codebase reads `var(--text-quaternary)` anymore once the `@theme inline` mapping and workspace `:root` copy were removed, so no rendered portal pixel changes. Left as-is would have failed SD-004's literal "no `--text-quaternary` declaration remains in any file" wording. Flagging this explicitly per the handoff-skill's non-obvious-decision rule.
- Also fixed two pre-existing, unrelated TypeScript build errors (`components/ui/status-badge.tsx` icon prop typing, `tests/unit/docs-markdown-editor-export-import.test.tsx` untyped mock tuple) so that `npm run build` — a hard constraint of this feature — actually passes. Confirmed via `git stash` that both errors existed identically on the pre-F006 commit, i.e. they were not introduced by this codemod; fixed them anyway because the spec's Definition of Done requires a clean build.
- `--tw-prose-td-borders: var(--line-row)` inside the (explicitly protected) prose block was repointed to `var(--border)` — same reasoning as above: `--line-row` no longer exists as a token, so leaving the reference would silently break table borders inside rendered docs/rich-text. The prose *rule* itself (selector, other properties) is untouched; only the value of one CSS custom property was swapped to point at a token that still exists.

## Notes for the next worker
- BSD `sed` on macOS silently ignores `\b` word-boundary syntax — always use `perl -pi -e` for word-boundary class-name codemods on this machine, not `sed -i ''`.
- When deleting a `@layer components { ... }` CSS block programmatically, count brace depth rather than searching for the first `}` — nested rule blocks make a naive scan truncate early (I hit this and recovered via `git checkout -- app/globals.css` before it was ever staged/committed).
- Grep patterns for "is this token still used" should also check Tailwind arbitrary-value bracket syntax (`bg-[var(--token)]`, `border-[var(--token)]`) in addition to the expected utility-class names (`bg-token`, `border-token`) — the spec's suggested greps for F011 missed three real usages this way.
