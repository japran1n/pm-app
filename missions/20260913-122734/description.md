# Description

_Captured: 2026-09-13T10:27:34Z_

Client-facing handover documents in the portal. Today the portal's "How we work" section (app/(portal)/portal/[workspaceSlug]/p/[projectId]/how-we-work) renders docs rows with doc_kind in (onboarding, feedback, portal_guide, handover) as plain text with link cards. We just seeded the first real handover document — a Webflow training manual with 8 Webflow University videos — and hit three limits. This mission fixes all three. (1) Rendering: doc content renders as whitespace-pre-line plain text, so markdown headings, lists and tables show as raw characters; and doc_links whose URL is a YouTube video should render as an inline youtube-nocookie iframe embed instead of a click-out card. (2) Templates: there is no doc template concept — task_templates exists for kind='task' only — so every project needs copy-paste, and fixing a mistake in one project does not fix the others. We need workspace-level doc templates and a "new doc from template" flow, so a PM can seed a project's handover pack in one click. (3) Placeholders: template text contains {{site_url}}, {{webflow_site_url}}, {{staging_url}} etc. These should resolve automatically from the project's existing project_links rows (kinds live, staging, webflow, figma, drive, gtm, analytics, search_console) plus a small set of manually filled per-project fields (e.g. collections, image specs, required fields, form recipients). An unresolved placeholder must be visible as a warning to the team and must never render as literal {{...}} to the client. Explicitly out of scope: per-client module progress tracking, checkboxes, completion percentages and rehearsal sign-off (decided against). Client-facing language stays English. No e-commerce variant. Stack is unchanged: Next.js App Router, Supabase with RLS, TipTap already a dependency, Supabase design system per CLAUDE.md.
