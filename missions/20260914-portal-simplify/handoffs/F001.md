## Decisions made
- Added `projectId: string` as a required second parameter to `getPortalFiles` rather than making it optional, since every caller (the one page route) always has a project id in scope and an optional param would let a future caller accidentally regress to workspace-wide behavior.
- Followed the exact `portal_enabled` filter pattern already established by `getPortalRequests` / `getPortalProjectOptions` in the same file (explicit `.eq("portal_enabled", true)` on the `projects` read, since RLS does not gate `projects` SELECT by that column) rather than inventing a new pattern.
- Left the legacy `/portal/<slug>/files` redirect page untouched — it already resolves via `getPortalProjects` (which already filters `portal_enabled`) and forwards to the new project-scoped URL, so it needed no change for these two assertions.
- Updated the page's copy from "across every project" to "on this project" since the query is now genuinely project-scoped; this is a copy-only change matching the corrected behavior, not a new UI decision.
