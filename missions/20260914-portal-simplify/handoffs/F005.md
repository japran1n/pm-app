## Decisions made
- **API shape**: `getWaitingOnYouCount(projectId: string, todayIso: string): Promise<PortalQueryResult<{ decisions, materials, total, overdue }>>`, in `lib/portal/waiting-on-you-count.ts`. Uses the codebase's existing `PortalQueryResult<T>` discriminant (from `lib/queries/portal.ts`) — same convention `getOpenApprovalsForClient`/`getClientDeliverablesForPortal` already use — so a failed read is a distinct, un-coalescable value from "the true count is zero."
- **Reused, did not duplicate, existing reads**: `decisions` = `getOpenApprovalsForClient(projectId).data.length` (that query already filters to `state === "pending"`, i.e. open approvals the client can act on — matches `badges.approvalsAwaiting`'s own source in spirit but this feature calls the query directly rather than importing `getPortalBadgeCounts`, since that function bundles unrelated fields (`deliverablesPastDue` computed differently) this helper doesn't need). `materials` = `getClientDeliverablesForPortal(projectId).data` filtered to `state !== "accepted" && state !== "waived"`. `overdue`'s materials half reuses the shared `isDeliverablePastDue` predicate verbatim — never re-derived.
- **Reconciled with `build-waiting-on-you-items.ts` rather than creating a third definition**: that module's `buildWaitingOnYouItems` is intentionally BROADER (adds `pending_client_approval` tasks, pending client-owned accounts, and a draft brief — the pre-simplify Overview "What we need from you" block). Per plan.md's F005 description ("open client decisions... + outstanding client materials"), F006's new "For you" page groups its list into exactly two buckets — decisions and materials — so this new helper is deliberately narrower and scoped to that specific pairing, not a competing "waiting on you" definition. Documented at the top of the new file so a future worker doesn't assume it's redundant with `buildWaitingOnYouItems`. `waiting-on-you-by-project.ts` is unrelated (a pure `Map` aggregation over an already-fetched task list, workspace-chooser-scoped) — no overlap to reconcile there.
- **`overdue` includes both categories.** Deliverables: `isDeliverablePastDue(state, dueAt, todayIso)`. Approvals: `PortalApproval` does carry a `dueAt` (nullable) but no existing predicate anywhere in the codebase derives an "approval past due" flag from it (checked `build-next-from-you.ts`, `lib/queries/approvals.ts`, `lib/queries/portal.ts` — none exist). Since `getOpenApprovalsForClient` only ever returns `state === "pending"` rows, this helper adds one small local `isApprovalPastDue(dueAt, todayIso)` (has a due date AND it's past) rather than inventing a shared cross-entity predicate that doesn't otherwise exist — this is new logic, not a duplicate of anything.
- **Exposed via the badge-count loader**: NOT done. `getPortalBadgeCounts` in `lib/queries/portal.ts` is a different shape (per-badge fields including sidebar-wide `approvalsAwaiting`/`deliverablesPastDue`, used by today's secondary nav) and F008 is the feature that rebuilds the sidebar into the 4-item nav with a single "For you" badge — wiring `getWaitingOnYouCount` into whatever nav-item builder F008 introduces is that feature's job, not a "trivial" exposure through the existing loader (the existing loader's two fields already mean something different and are consumed by badge UI F008 is about to replace). Flagged below as the exact integration point for F006/F008/F010.
