## Decisions made
- **Subtitle rendered inside the same `<Link>` as the tab label**, stacked via `flex flex-col`, rather than a separate sibling element — keeps one hit target per tab and avoids a second row of markup outside the existing pill-nav loop. Uses `text-xs font-normal text-muted-foreground` (not `text-tertiary-foreground`, per CLAUDE.md: tertiary is decorative-only and this text is information the PM needs to read to know where their edit lands) and plain Tailwind (`text-xs`), no deleted `text-mini`/`text-micro` utilities.
- **"Phases → Home"**: the spec says "if phases show on overview" — verified directly (Overview page, `<PhaseTimeline>`, unconditionally rendered whenever the phases read succeeds) — so Phases gets the subtitle unconditionally, matching the current always-on behaviour rather than adding a new gate that doesn't exist anywhere else.
- **Architecture note text is "Shared pages appear to the client under Site map"** (exact wording from this feature's own task prompt), placed in `ArchitectureViewToggle`'s existing header row (the toggle between Column/Canvas views) rather than in the route's `page.tsx` — that toggle component is the one place both the board and canvas views already share a header, so the note appears regardless of which view is active, without duplicating it in two places.
- Used `data-testid="architecture-client-visibility-note"` and `data-testid="settings-nav-client-sees-<slug>"` (not a class-based selector) for both new tests, matching this codebase's existing `data-testid`-driven assertion convention (e.g. `approval-card.tsx`'s own `data-testid="approval-due-chip"`).
