## Decisions made
- **`extractWorkspaceSlug` (item 7)**: added to `lib/actions/portal-revalidate.ts` — takes a `workspaces(slug)` join result (object or array, since PostgREST's `!inner` vs plain-join shape differs) and returns the slug or `undefined`, `console.warn`-ing (via `logger.warn`) when missing. Used at every new call site in `ordering.ts`, `attachments.ts`, `duplicate.ts`, `bulk.ts`, `brief.ts`, `docs.ts`, `architecture.ts`'s `importPages`. NOT retrofitted onto every pre-existing F004/F004b call site (`comments.ts` keeps its inline unwraps, `architecture.ts`'s existing `createPage`/`renamePage`/etc. keep theirs) — that would have been a much larger diff for a purely cosmetic win on already-correct, already-tested code; flagged as out-of-scope follow-up below.
- **`tasks/duplicate.ts`**: `client_visible` is deliberately NOT copied from the source row on insert — it defaults to `false` (same as every other task-creation path in this codebase, per the F090 migration). The new revalidate call is gated on the INSERTED row's own `client_visible` (which will always read `false` today), not the source's — documented inline as future-proofing rather than a currently-live code path, per the instruction's "gated on client_visible where the task is involved."
- **`tasks/bulk.ts`**: added one shared `revalidatePortalForBulkContexts` helper that dedupes by `(workspaceSlug, projectId)` pair and calls `revalidatePortalProject` once per unique pair across the whole succeeded-ids batch — never once per task, matching this file's own "one statement/call per batch" performance convention. `bulkRestoreTasks` needed no change: it already delegates to `restoreTask` per id (F004b already added the portal-revalidate gate there).
- **`brief.ts`**: unlike every other file in this round, this module's mutations never load a workspace slug anywhere (confirmed: zero `workspaces` table references before this change) and the brief questionnaire is ENTIRELY portal-visible (no per-row `client_visible` gate exists on `brief_questions`/`brief_answers`/`briefs`), so a small shared `revalidatePortalForBriefProject(supabase, projectId)` helper does one extra lookup per mutation rather than widening an existing select — wrapped in its own whole-function try/catch (non-fatal) after discovering it broke `tests/unit/f075-approval-state.test.ts`/`f077-withdrawal.test.ts`'s narrower Supabase mocks (see below).
- **`docs.ts`**: added a parallel `revalidatePortalForDoc(supabase, docId)` helper (distinct from the file's existing `/w`-broad `revalidateDocs()`) that re-reads the doc's CURRENT `client_visible` value AFTER the write — this correctly fires on both directions of `setDocClientVisibility`'s toggle (sharing AND unsharing), not just sharing. `deleteDoc` needed a before-delete read since the row won't exist to check afterward.
- **Regression caught and fixed**: `brief.ts`'s new helper initially threw synchronously (`.select is not a function`) against `tests/unit/f075-approval-state.test.ts`/`f077-withdrawal.test.ts`'s existing narrow Supabase mocks (which only stub `.from().update()...`, no `.select()` on a second `.from("projects")` call), turning `approveBrief`/`withdrawBriefApproval`'s real success path into an unhandled rejection. Fixed by wrapping the ENTIRE helper body in try/catch (not just around the query), matching every other `revalidate*` helper's own non-fatal convention in this codebase — this is the correct fix, not a workaround, since a portal-refresh side effect must never be able to turn a real state-change into a reported failure.
- **`architecture.ts` item 3 (reorderSections/reorderPages slug-vs-projectId bug)**: both maps were `Map<slug, projectId>`; fixed to `Map<projectId, slug>`. Two different projects in the SAME workspace share one slug, so the old keying silently dropped every project but the last one seen for a given slug when a single reorder batch spanned multiple projects.
- **`architecture.ts` item 6 (`setSectionClientVisibility`)**: the parent-page lookup now runs strictly after `canWrite` passes (previously ran before, wasting a query on a caller about to be rejected) and only when `visible === true` (unsharing never needs the "page still hidden" hint). Added `.is("deleted_at", null)` so a soft-deleted parent page reads as "no page found" (`pageHidden: false`), not "hidden." A lookup error is now logged via `logger.error` rather than silently defaulting to "not hidden."
- **`architecture.ts` item 2 (`importPages`)**: added the unconditional portal revalidate matching `createPage`'s own convention (imported pages default `client_visible: false`, same as a single `createPage` call, so this has no live behavioral effect today but is consistent with its sibling rather than inventing a client_visible gate `createPage` itself doesn't have).
- **`tasks/edit.ts` item 8**: moved the `revalidatePortalProject` call out of the `/w` `try/catch` — purely a readability/consistency fix (the helper already has its own internal non-fatal try/catch), no behavior change.
- **`app/(portal)/.../files/page.tsx` item 9**: comment-only change per the instruction; `getPortalFiles`'s query shape and contract are untouched.
