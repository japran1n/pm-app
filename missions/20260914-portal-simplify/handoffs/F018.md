## Decisions made
- Item 1 (AS-007/AS-018): removed the old "Waiting on you" card from `PortalOverviewLive` entirely rather than wiring it to `getWaitingOnYouCount`, per the spec's "prefer removal" instruction. Confirmed by grep that `PortalOverviewLive` is only ever mounted from the per-project Overview page (`p/[projectId]/page.tsx`) — the workspace-chooser page (`app/(portal)/portal/[workspaceSlug]/page.tsx`) reads `overview.waitingOnYou` directly for its own per-project badge count and never imports this component, so nothing else observes the removal. Dropped the now-unused `waitingOnYouFailed`/`projectId` props and the realtime reconcile wiring (`usePortalOverviewRealtime`, the `pending_client_approval` predicate) that only ever fed that card; `reconcilePortalRealtimeTask` itself is untouched since `components/task/task-list.tsx` still uses it for something else. Left the underlying `getPortalWaitingOnYou` project-scoped fetch and `projectScopedOverview.waitingOnYou` field in `page.tsx` as-is (harmless, now-unconsumed-by-the-live-component data) rather than widening the diff further — see Out-of-scope below.
- Item 2 (sidebar badge contrast): rather than inventing a new colour, the active-row badge borrows `--primary-foreground` (the token already guaranteed to read against `--primary`, the same fill the active row itself uses) for its border/fill/text, overriding the badge's normal `currentColor`-derived tint only when `active` is true. Keeps the design system's "colours are derived, not hand-written" rule — no new hex, reuses an existing semantic token.
- Item 3 (mobile nav overflow): reduced gap/padding/text-size/icon-size specifically for `layout === "mobile"` on both `NavRow` and the `ProjectNavGroup` toggle button (the previous fix only touched `NavRow`, but the "Project" button used the same desktop sizing and was the item actually getting clipped at 375px). Kept desktop sizing untouched.
- Item 4 (duplicate titles): converted the body `<h1>` in `for-you/page.tsx` and `conversation/page.tsx` to `sr-only` rather than deleting it outright, so each page keeps its own accessible heading — matches the sibling routes (`pages`, `hours`, `results`, `scope`, `site`, `architecture`) which render no visible body title at all, since the topbar already prints the route's title from `STATIC_ROUTE_TITLES`. Did not touch `files/page.tsx` or `how-we-work/page.tsx`, which have the same pattern but weren't named in this feature's scope.

## Out-of-scope work needed
- `p/[projectId]/page.tsx` still fetches `getPortalWaitingOnYou(project.id, project.name)` and threads it into `projectScopedOverview.waitingOnYou`, which is now dead weight since `PortalOverviewLive` no longer reads that field. A future pass could drop that fetch and the `PortalOverview.waitingOnYou` field entirely (checking `lib/portal/waiting-on-you-by-project.ts` and the workspace-chooser page's own use of `overview.waitingOnYou` first, since `getPortalOverview` still needs to produce it for that page).

- `files/page.tsx` and `how-we-work/page.tsx` have the same duplicate-title pattern (visible body `<h1>` under a topbar that already shows the same title) as the two pages fixed here, but weren't named in this feature's bug list — a follow-up could apply the same `sr-only` treatment for consistency.
